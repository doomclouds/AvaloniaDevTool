# 协议监视器

Inspector 的“协议”页录制本会话真实 Native RPC 的请求、响应和通知，包括本机管道与 WebSocket 共用的 `RpcPeer` 路径。它观察本项目的协议，不连接原版私有协议，也不是抓包器或 MCP stdio 录制器。

## 录制与关联

默认关闭录制，正文默认不录制。可以在连接前点击开始，以捕获 `session.info` 握手；停止保留当前历史，清空保留录制状态，重新开始建立新的录制边界。断开和重连保留已录制历史，每次连接使用独立关联空间，避免不同连接从 1 开始的请求 ID 混淆。

`RpcPeer.TraceObserved` 在实际帧收发路径发布解码观察。记录以连接 ID、请求方向和请求 ID 关联，双向调用可以同时存在相同 ID。请求行在响应到达时原地更新为成功或错误；调用方取消、超时、断连、停止录制及清空后的未关联响应均有明确状态。迟到响应保留取消错误，不冒充普通成功。有效帧仍可能无法转换为调用方要求的类型，此时同一行回填 `ClientFailed`／`invalid_response`。

耗时使用单调 `Stopwatch`，从开始写请求帧到响应观察或本地终态，不含客户端写队列等待；UTC 时间用于展示。字节数是序列化 JSON 帧正文的实际长度，不含四字节长度头；发送观察发生在开始写入前，所以表示尝试发送的长度，不证明对端已接收。监视器不解释应用处理器执行耗时的内部组成。

## 正文与预算

开启正文后，参数和结果分别保留有效 JSON 投影，单份最多 16 KiB，深度最多 12、节点预算 128，字符串最多 512 字符；数组、对象、巨大数值和长键均明确截断。它不保留完整 4 MiB 帧或活业务对象。包含 token／password／authorization／secret／credential／apikey／privatekey 的字段名会脱敏；正文仍可能包含应用数据，开关在开始录制前选择。WebSocket Authorization 建连头不经过本 RPC 观察路径。

历史最多 500 行、按记录保留的 UTF-8 文本加固定元数据计算最多 2 MiB，先到任一上限就淘汰最旧行及其关联索引。投影和历史均有独立预算。默认关闭正文时不执行投影，也不保留请求或结果。观察者异常被隔离，不能终止传输；录制代码不发送额外 RPC，工具每 200 ms 在 UI 线程读取本地快照。

界面可以按方法、状态或错误码筛选，并只看错误；选择行后分别查看参数、响应、字节数和耗时。停止后仍可浏览或清空。外部 XamlMcp 后端没有本项目 RpcPeer，因此页面禁用，不显示伪造通信。

## 依据与验证

原版公开 [Settings](https://docs.avaloniaui.net/tools/developer-tools/settings) 说明存在通信监视入口；此前产物研究只确认 `Recording`、`Filter`、`RequestArguments` 和 `Response` 等模型线索，见 [原生分析](research/native-deep-analysis.md)。以上关联、容量、脱敏和取消状态是本项目实际设计与实现，不宣称恢复原版 wire format 或内部算法。

`RpcTraceTests` 通过真实双向命名管道验证相同 ID 的反向调用、错误和通知、取消后迟到响应、类型解码错误；另用大量 Unicode JSON 验证可解析截断、正文及历史预算、不同连接／清空／停止的关联边界。`ProtocolMonitorTests` 加载真实 AXAML 并连接 Agent，使用页面按钮录制握手和失败属性请求，验证过滤、停止保留、清空不终止连接，以及默认元数据模式与重连 ID 隔离。具体同批次结果见 [测试记录](testing.md)，不能由这些测试推导跨平台桌面已验。

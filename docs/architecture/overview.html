两条执行通道，共用当前附加目标

现状 · 已有实现

Agent 在目标进程内访问 Avalonia；Windows worker 在独立进程内访问 UIA 和 OS 输入。

1. MCP 客户端 → CLI 进程

标准 stdio / HTTP MCP 调用工具；CLI 管理当前目标，转换参数和返回内容。目标操作仍在宿主所在电脑本地执行。

managed 通道：Client ⇄ 命名管道 RPC

2. 目标应用内 Agent

UI 线程调度 → 会话与对象身份 → 树、属性、资源、输入和诊断服务。

native 通道：NativeAutomation ⇄ 独立 IPC

3. 独立 Windows worker

UIA、owned 窗口和 OS 输入。请求门独立，managed 等待模态弹窗时仍可操作弹窗。

4. 文件附加 → Previewer 进程

CLI 启动并回收预览；预览加载项目与 XAML、挂载同款 Agent，Client 改连此 Agent。

调用 / 内部 RPCnative 独立 IPC进程所有权

两种目标入口

已有应用：应用挂载 Agent → MCP 宿主 → 附加目标。文件预览：MCP 宿主 → attach-to-file → 自建 Previewer，无需预先启动消费应用。

可选接入

Remote 将 WebSocket 接到同一 Agent 会话；Logging 适配应用日志源。两者均为可选依赖。

释放范围

断开清理本会话的覆盖、监听、流和自建进程；外部附加的应用由用户拥有。

9 个生产项目，编译引用与进程分发分开看

现状 · csproj 直接依赖

箭头 A → B 表示 A 引用 B。6 个类库承载能力，3 个可执行项目提供宿主和隔离进程。

Cli · Exe编译 → Client、NativeAutomation；构建分发 → Previewer、条件 Windows worker
Client · 类库编译 → Protocol
Agent · 类库编译 → Protocol
Protocol · 类库无项目引用；保持与 Avalonia、MCP、Windows UIA 解耦
NativeAutomation · 类库无项目引用；管理原生会话和独立 worker IPC
NativeAutomation.Worker · Exe编译 → NativeAutomation；Windows UIA / OS 实现
Previewer · Exe编译 → Agent
Remote · 类库编译 → Agent；可选 ASP.NET Core 依赖
Logging · 类库编译 → Agent；可选 Microsoft.Extensions.Logging 依赖
ReferenceOutputAssembly=false 表示 CLI 不把 Previewer / worker 当作编译引用；二者仍须构建并分发到 previewer/ 和 native-worker/。Windows worker 按宿主和目标 RID 条件选择。

内网 HTTP 标准 MCP → A 的 /mcp

电脑 A · 完整执行宿主

同一 Windows 用户交互桌面内运行 Tools、会话编排、Client 与 NativeAutomation。

Client ⇄ A 本机命名管道 RPC

A 上的 Avalonia 应用 + Agent SDK

目标对象和 UI 操作在应用进程内执行。

A 上的 worker 与 Previewer

原生操作经独立本地 IPC；需要文件预览时由 A 启动 Previewer，并通过管道连接其 Agent。

1. A：监听地址和端口

在 A 已构建或发布的 CLI 目录运行。监听 IP 和端口均可配置，请将示例 IP 替换为 A 的实际地址。

dotnet AvaloniaDevTool.Cli.dll mcp --transport http --listen 192.168.1.50 --port 7443

2. B：Codex 的服务 URL

与其他 MCP 相同，Codex 加载标准 config.toml 的 URL 条目后自动连接 A 已运行的服务，无需手工连接工具。URL 中的 IP 和端口须与 A 的可访问地址匹配。 

[mcp_servers.avalonia_testpc]
url = "http://192.168.1.50:7443/mcp"

本阶段不设 Token，也不配置 command 或 args。

3. 工具：照常描述目标与动作

MCP 连接完成后，先附加 A 上的应用，再调用 tree、props、ui-click。工具参数不重复传 IP。

attach-to-app {}
→ 用返回的应用 id 附加
→ tree {}
→ props / ui-click

服务 URL 选择执行电脑；attach 选择该电脑上的目标应用，节点和路径由 A 解释。

listen
A 的本地绑定地址。示例 192.168.1.50 可配置；0.0.0.0 表示监听 A 的所有 IPv4 网卡，不能填写为 Codex 的访问 URL。
访问 URL
B 能访问的 A 地址、端口和路径，例如 http://192.168.1.50:7443/mcp。这里是可替换的配置示例，不表示该 IP 已有常驻服务。示例端口 7443 不表示自动启用 HTTPS，协议由 URL 的 http:// 确定。
路径与执行桌面
XAML、项目、构建输出和文件路径均位于 A；宿主、目标应用及 worker 在 A 的同一 Windows 用户交互桌面执行。
Session 与 Token
允许多个 HTTP 协议会话，同时只有一个桌面控制租约；发现和列工具不占桌面，attach 或首次目标操作取得控制，detach 释放控制。Session 管理资源生命周期，不是认证 Token；本阶段不配置 Token。
实现状态
HTTP /mcp、监听参数、会话与控制租约已实现；HTTP 固定提供 agent 目录 44 项工具，stdio 保留现有历史 profiles。详见 内网 MCP 部署。
验证范围
已验证本机 HTTP 的真实模态并发、文件字节/hash、重新打开与 PNG，以及 WSL 协议互通。WSL 非回环地址访问仍有失败记录；独立双机网络待验。完整条件与结果见 测试记录。
